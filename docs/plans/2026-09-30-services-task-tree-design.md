# Running Tasks and Dependency Tree Implementation Plan

**Goal:** 将 One CLI TUI 左侧拆成动态的运行中任务列表和完整依赖树，并补齐日志文本选择与复制，让正在执行的任务、完整依赖和可复制日志都容易访问。

**Architecture:** 所有节点统一为任务，不区分服务类型，不新增服务配置。上方列表由可靠的任务生命周期事件驱动，下方始终保留完整任务图；两处共享规范任务身份、日志和阅读位置，mise 继续负责整次调用的调度。复制通过日志选区和独立剪贴板适配完成，终端原生复制模式作为兼容入口，不依赖任务生命周期接入。

**Tech Stack:** Go、Bubble Tea、Lip Gloss、现有 taskui 日志存储、任务生命周期适配、zh-CN/en-US 字典。

状态：已获批准并完成实现。下文保留产品约定及实施顺序，第 11 节记录最终接入方式、实际验证和待人工验收项。

根据最新反馈，取消之前的服务类型、∞ 类型标识和 manifest 的 task_ui.services 配置。上方名称改为“运行中任务”，下方为“任务依赖树”。使用任务状态决定上方成员，不要求用户理解或声明什么是服务。

新增需求：TUI 中恢复文本选择与复制。用户主要使用 VS Code 集成终端，因此以 macOS 上的 VS Code 为主要验收环境；SSH/Remote 和 tmux 作为兼容验证范围，不假定用户正在使用。

## 1. 用户能看到的行为

- 任务尚未启动时，只显示在下方树中。
- 任务实际启动后，自动加入上方运行中列表；下方对应节点仍保留。
- 任务成功、失败或取消后，从上方移除，下方保留节点和已确认的结果。
- 构建、健康检查、常驻进程使用同一规则：运行期间在上方，结束后仅保留在下方。
- 下方树始终覆盖本次运行的全部任务和入口，不因状态变化移动节点或改变依赖层级。
- 用户正在查看的任务结束时，继续显示其日志，导航选择定位到下方同一节点，保留阅读位置和搜索条件。

“降到下方”指移除上方的快捷入口。任务从启动前就存在于下方树中，不需要结束时重新插入树或改写依赖。

## 2. 布局示意

以下是布局示意，具体树节点和状态以本次调用为准：

```text
全部日志                         │ 当前任务日志
                                 │
运行中 · 3                       │
  ● _drama:server-run             │
  ● _drama:desktop-renderer       │
  ● _drama:desktop-host           │
                                 │
任务依赖树                       │
▾ dev                            │
├─ ▾ ● _drama:server-run          │
│  └─ ▸ ✓ _drama:server-ready     │
├─ ✓ _drama:server-health         │
└─ ▸ dev:desktop                  │
                                 │
选中项完整名称与状态               │
```

启动早期，构建和检查任务会暂时出现在上方；结束后逐项移除，常驻任务自然留在上方。没有“服务退化为任务”的类型变化，只有任务状态变化。

## 3. 状态规则

| 状态 | 上方列表 | 下方树 |
| --- | --- | --- |
| 等待启动或等待依赖 | 不显示 | 保留，显示等待状态 |
| 正在执行 | 显示 | 保留，显示运行状态 |
| 成功完成 | 移除 | 保留成功结果 |
| 执行失败 | 移除 | 保留失败结果与日志 |
| 已取消 | 移除 | 保留取消结果与日志 |
| 缓存复用或无需执行 | 不显示 | 有可靠事件时显示对应结果 |
| 无法确认状态 | 不冒充运行中 | 保留，明确显示未知 |

补充约定：

1. “未结束”仅包含实际启动、尚未结束的任务。不能把计划里尚未开始的全部节点塞进上方。
2. 一个任务有多条 run 命令时，从任务开始到全部命令结束视为一个连续执行过程；中间步骤退出不能提前移除条目。
3. 没有执行命令的纯聚合节点保留为树的组织节点，不把它等待依赖的过程当成正在执行的独立进程。
4. 任务启动但不输出日志，仍进入上方；运行中的进程长时间安静，仍保留。
5. 缓存复用产生的回放日志不能被当作真实启动。
6. 状态属于本次调用中的任务执行实例。任务确实重新执行时，可以再次进入上方；历史事件不能覆盖新实例。
7. 快任务的开始与结束若发生在同一刷新周期，可以只在树中看到最终状态，不人为延迟移除来制造闪烁。

状态文案和符号同步支持中英文；符号使用统一显示宽度的方案，最终选择在终端验证后确定。

## 4. 导航、滚动与阅读位置

- Tab 保持侧栏/日志两种焦点。侧栏 ↑/↓ 依次选择全部日志、运行中条目和可见树节点。
- 上方 Enter 进入选中任务日志；→ 定位下方同一任务的主节点，展开祖先路径并滚动到可见位置。
- 下方 ←/→、Enter、空格保留现有展开、折叠和共享引用跳转行为。
- 上下两处选择同一任务时，共享日志、搜索、跟随设置和阅读位置。只有当前操作位置具有键盘焦点，另一处使用关联高亮。
- 上方列表按启动顺序保持稳定，移除已结束项后保留其余任务的相对顺序，不能每次来日志都重排。
- 正在查看的上方条目结束时，选中任务身份不变，改为关联下方节点。若焦点在日志，保持日志焦点；若在侧栏，定位下方节点。其他条目结束不移动用户的选择。
- 上方与树各自滚动。成员变化不重置树的折叠状态或滚动位置；分区高度保持稳定，避免频繁新增/移除任务时整棵树上下跳动。
- 上方可见行数约占侧栏可用高度的三分之一，过多运行任务在该区滚动。没有运行任务时显示“暂无运行中任务”，等待后续启动。
- 初始依赖树默认显示入口和下一层，深层节点按需展开；暂不根据完成事件自动折叠用户正在阅读的分支。
- 右侧选中项标题显示完整名称并按显示宽度换行。小于 70 列时继续在全宽侧栏和日志之间切换。
- 日志区域支持拖选文本，选区复制和原生复制模式的具体规则见第 10 节。搜索输入时复制快捷键不截获普通输入；清除选区优先于清除历史搜索。

## 5. 完整依赖关系

下方树保留服务进程、构建、检查、健康等待和聚合入口的原始位置，不过滤运行中任务，不在结束后把它移到其他分支。

同一共享依赖只展开一次，其余位置使用 ↪。共享引用和上方运行中入口均指向同一任务身份；多一个入口不会增加一次执行或日志订阅。

depends 与 wait_for 等关系分开表示。wait_for 只关联本次计划中已经存在的节点，不能为了画出一条等待边就新增调度任务。动态配置不能可靠解析时，明确说明展示限制。

## 6. 可靠的生命周期数据

实现前，One 的 TUI 使用普通日志管道，并只监听整组 mise 子进程退出；单任务状态为 unknown。仅凭现有日志不能实现准确的运行中列表。

本功能需要可靠的任务级开始和结束事件，不能用任务名称、日志前缀、第一行输出、完成文字、沉默时间或任务时长猜测状态。

接入顺序：

1. 核对实际使用的 mise 版本与结构化能力。仓库托管版本和最低版本目前为 2026.9.7，不能只凭最新文档假定旧版本具备同样能力。
2. 优先评估原生任务生命周期或 tracing 接口，验证“事件何时送到 One”，而不只是事件中记录的时间。任务结束后才导出的 trace 无法单独支持实时运行列表。
3. 官方 OpenTelemetry 文档描述了任务 spans、跳过/取消信息，但其任务 span 起点是调度器接手任务，早于进程启动。不能直接把 span 起点当作已经启动进程；还需验证实时开始通知、版本支持和导出时机。[mise OpenTelemetry](https://mise.jdx.dev/tasks/opentelemetry.html)
4. 如果原生接口不能满足，评估在实际任务执行边界增加内部事件采集适配。需要先证明它能覆盖整个任务，保留多步骤命令、shell、file task、参数、工作目录、环境、缓存和取消语义；不预先承诺通过简单包装某一条 run 命令解决。
5. 事件通道与原始日志分离，使用本次会话和规范任务身份关联；只传递必要的事件、序列、时间和退出结果，不把业务日志内容当成状态协议。
6. 事件去重，校验执行实例，防止并发调用互相污染或迟到结束事件关闭新的执行实例。通道异常时显示状态未知，不能把所有任务标为完成。
7. 用户配置保持不变，仍由一个 mise 调度器决定执行次序和并行度。stream/raw 模式的原生输入输出与退出语义继续保留。

实施验证确认：最低版本 2026.9.7 没有可用的任务事件接口，新版 tracing 也不能提供所需的实时进程启动通知。用户已明确授权扩展托管 mise。最终在固定上游源码的进程启动及完整任务结束边界加入独立事件通道，具体见第 11 节。

## 10. 文本选择与复制规划

### 10.1 已核对的问题与环境

实现前，taskui.View 开启 AltScreen 和 MouseModeCellMotion；Update 只处理点击及滚轮，没有拖选、选区或剪贴板动作。鼠标捕获阻止了终端通常的拖选路径。现已实现应用内拖选和关闭鼠标捕获的原生复制模式；VS Code 的实际粘贴结果仍需人工验收。

VS Code 官方文档说明：应用启用鼠标事件模式后，鼠标交互交给应用；macOS 的 Option 强制选择需要启用 terminal.integrated.macOptionClickForcesSelection。[VS Code Terminal Basics](https://code.visualstudio.com/docs/terminal/basics/?azure-portal=true)

本机 VS Code 安装版本为 1.139.1，其该选项默认值为 false；实施时再次记录实际验收版本和设置。One 的复制入口不依赖修改该选项，也不自动修改编辑器设置。

### 10.2 方案比较

| 方案 | 优点 | 取舍 |
| --- | --- | --- |
| 应用内拖选 + 明确复制动作，推荐 | 保留滚轮和侧栏点击，可按日志逻辑行复制，避免混入侧栏 | 需要选区模型、坐标映射和剪贴板适配 |
| 原生复制模式，兼容入口 | 关闭鼠标捕获后由终端选择，支持用户熟悉的复制快捷键 | 需要临时固定画面；原生选区本身由终端管理 |
| 始终关闭鼠标捕获 | 改动小，普通终端拖选恢复 | 会失去现有点击和滚轮交互，不作为默认方案 |

采用前两种组合。原生复制模式可以先独立交付；最终默认保留鼠标交互，并提供日志区拖选与应用复制。

### 10.3 用户操作

| 操作 | 行为 |
| --- | --- |
| 在日志区按住左键拖动 | 建立文本选区，按字符范围高亮；跨行选择 |
| 释放鼠标 | 保留选区，不自动覆盖剪贴板 |
| 有应用内选区时按 y | 复制所选文本 |
| 无应用内选区时按 y | 打开复制菜单，明确选择当前可见日志或完整任务名称 |
| 按 c | 进入原生复制模式，显示当前日志视口的全宽文本快照，关闭鼠标捕获 |
| 原生复制模式中拖选、按终端复制快捷键 | 使用终端自己的选区和剪贴板操作，例如 VS Code/macOS 的 Cmd+C |
| Esc | 按当前交互优先级退出复制菜单/原生模式，或清除应用选区 |
| f | 清除应用选区并继续跟随最新日志 |
| Ctrl+C | 始终取消任务，保留现有含义 |

y 和 c 仅在普通导航状态触发；编辑搜索条件时按字符输入处理。菜单和原生模式结束后恢复原焦点与阅读位置。

应用内高亮与终端原生选区是不同状态，不能承诺 Cmd+C 会读取 One 的内部选区。应用内选区用 y；原生模式用终端复制快捷键。底部提示必须明确标出当前可用操作。

原生模式关闭鼠标捕获后，鼠标由终端管理，One 不读取终端选区或剪贴板内容。该模式的 y 不自动切换到另一个复制范围。

### 10.4 选区与复制内容

- 选区记录规范任务身份、稳定日志条目身份和 Unicode 字素边界，不只保存屏幕行列或字节位置。
- 根据上一帧实际渲染的日志区域建立坐标映射，扣除标题、侧栏、分隔线和页脚；拖出日志区域时裁剪边界，不选中另一区域。
- 开始拖选时暂停该日志视图的自动跟随，固定坐标与内容快照；后台任务继续运行，日志继续接收。
- 鼠标释放后选区保留，直到明确清除、选择新范围或切换到不同任务。上下两处选择同一任务不清除选区。
- 窗口缩放时按逻辑文本范围重新映射选区，不因显示宽度变化复制错位。
- 对正在被回车覆盖的进度行，复制选择时的文本快照，后续刷新不偷偷改变选中的内容。
- 默认复制可读纯文本，剥离 ANSI 颜色、超链接控制序列和界面装饰。保留日志内容与原本显示的任务前缀。
- 同一逻辑行因窗口宽度分成多行时，复制不插入额外换行；原始日志的真实换行保留。
- 中文、emoji、组合字符不能被拆成半个字符；保留日志内部缩进和空行，不把视口补齐空格复制进去。
- 搜索结果中的选择只复制当前可见匹配内容，不把隐藏的未匹配日志带入。
- 复制当前可见日志时，按视口覆盖的逻辑文本范围复制，不顺便复制当前任务全部历史。
- 复制任务名称时使用完整规范任务名，即使侧栏标签已经截断。

### 10.5 剪贴板策略与结果提示

现有 Bubble Tea v2.0.10 提供 SetClipboard，通过 OSC 52 写终端剪贴板，源码同时说明并非所有终端都支持。因此不能仅因为命令已发送就显示“已复制”。

规划的适配策略：

1. 本地可确认的桌面运行环境优先采用系统剪贴板写入，并根据实际返回结果显示成功或失败。当前 macOS 以本地写入和 VS Code 中粘贴结果为首要验收路径。
2. 已知远程运行环境不能把远端机器的系统剪贴板当成用户本地剪贴板；评估使用终端 OSC 52，经过 VS Code/Remote、SSH 和 tmux 的实际验证再确认支持范围。
3. OSC 52 没有可靠写入回执时，提示“已发送复制请求”，提供原生复制模式入口，不伪造成功状态，也不读取用户剪贴板来验证。
4. 本地复制失败、终端协议被屏蔽或内容超过支持大小时，保留选区并给出明确失败/限制提示；不静默截断内容。
5. 剪贴板动作异步执行，错误不取消业务任务。复制菜单、选区或后备模式不改变任务退出码，也不阻止整次 mise 调用完成后自动退出。
6. 只响应用户明确的复制操作，不因日志出现就写剪贴板；不将日志或剪贴板内容写入额外诊断日志。

实际后端为 macOS pbcopy、Windows Set-Clipboard，以及有桌面环境时的 Linux wl-copy/xclip；SSH 和没有本地后端时使用 OSC 52，并只报告请求已发送。自动化测试注入模拟后端，不读取或写入开发者真实剪贴板，也不修改 VS Code 配置。

### 10.6 原生复制模式的稳定性

- c 进入时保存当前任务、阅读位置、跟随状态与可见日志文本，呈现全宽纯日志快照，减少跨列选择混入侧栏的情况。
- 关闭鼠标报告，固定画面刷新；只是固定展示，不暂停进程或日志收集。
- Esc 返回时恢复鼠标模式、分区布局和阅读状态。此前跟随最新输出的视图恢复跟随，此前停留历史位置的视图保留位置。
- 尺寸变化重新排版同一份快照；不从新日志中重新生成选择内容。
- q、Ctrl+C 和整次调度结束仍执行原有退出与清理。发生异常时也恢复终端模式。

### 10.7 复制专项验收

主要环境为 macOS + VS Code 集成终端默认设置。真实剪贴板粘贴验证与 PTY 协议测试分开记录；仅观察到 OSC 52 输出不算剪贴板成功。

验收场景：

1. 拖选单行中的 URL、路径和错误文本，按 y 后在 VS Code 临时文本中粘贴，内容一致。
2. 多行日志、中英文混排、emoji、长行软换行、ANSI 颜色和空行复制准确。
3. 日志持续产生时选区保持稳定，复制结果不被最新输出替换。
4. 两区列表动态变化、任务结束或窗口缩放时，选区不复制到错误任务或屏幕装饰。
5. 完整任务名称、当前可见日志和全部日志视图的复制范围明确。
6. 原生复制模式中可普通拖选并使用 Cmd+C，Esc 返回后侧栏点击和滚轮恢复。
7. Ctrl+C 仍能停止任务；搜索中输入 y/c、菜单 Esc 和选区 Esc 行为正确。
8. 剪贴板失败或终端能力不足时提示准确、选区保留、进程继续运行。
9. SSH/Remote 和 tmux 的实际支持范围在验证后记录，不根据本地成功推断远程成功。

自动化覆盖及仍待人工执行的环境验收见第 11 节。

## 11. 实施记录与验证

### 11.1 最终接入

- 固定 mise 2026.9.7 上游提交 `0db3fbe9efcee1944bc4990434c1a5ebcb480fca`，校验源码 SHA-256，使用原 Cargo.lock 和 Rust 1.95.0 构建。事件补丁位于 `packages/cli/tools/build-task-runtime/patches/one-task-events.patch`。
- TUI 使用内嵌的本平台压缩运行时，在 One 私有目录按内容摘要提取；提取有文件锁及摘要校验。保留现有项目变量注入、缓存目录和任务定义，stream/raw 保持原有运行时选择。
- 独立的 loopback TCP NDJSON 通道使用随机会话令牌认证；事件只含序列、任务规范名、执行实例和状态。协议环境变量在任务进程启动前移除，子任务不会继承事件凭据。
- 调度器接手任务时进入 preparing，成功创建真实进程后进入 running，整个任务执行返回后结束实例。多条 run 命令共用实例；聚合任务不进入 running，缓存回放不生成启动事件。
- Go 状态模型验证序列和转换，合并同一规范任务的并发实例。断流后未确定状态显示未知，不从日志推断。
- 上方运行中列表和下方完整树共享任务身份、日志及阅读位置；等待边仅引用已选任务，不能新增调度。树默认折叠深层分支，两个区域独立滚动。
- 拖选使用上一帧的日志视口及字素边界，冻结可见文本但继续收集日志。y 复制选区；无选区时菜单提供 v 复制可见日志、n 复制完整任务名。c 显示全宽快照并关闭鼠标报告，Esc 恢复。
- 新增 `one run prepare-task-runtime`、`one run verify-task-runtimes`；CI 为 Linux/macOS 的 amd64/arm64 和 Windows amd64 构建运行时并接入测试及发布。生成资产和 Cargo 缓存不纳入 Git。
