# One Electron

Read the manifest group and all three package.json files before changing paths.
For a project named `desktop`, the group contains:

- `apps/desktop-renderer`: React, Vite, shadcn/Base UI, and Tailwind.
- `services/desktop-main`: Electron lifecycle, native capabilities, Awilix,
  tsdown, development launcher, and electron-builder packaging configuration.
- `packages/desktop-preload`: the contextBridge API and its shared types/build.

Use the user's actual project name in imports, package names, artifact paths,
and group task references. Do not create a nested One workspace or move these
projects under the main service. Discover tasks with `one run`; start a group
with `one run <group>:dev`.

Keep main-process services as factory functions with explicit dependencies.
Register them using the existing Awilix container and lifetime conventions;
do not introduce decorators, class-based Inversify bindings, or a second DI
container. Keep cleanup and window lifecycle ownership explicit.

The renderer uses the typed preload API. Expose narrow contextBridge methods;
keep Node access, filesystem operations, and privileged work in main.
Update main handlers, preload contracts, and renderer callers together when
changing IPC. Validate incoming arguments, sender window, main frame, and trusted URL in
the privileged process. The starter exposes only `getAppInfo()`; add narrow
methods when the user requests privileged features, never raw invoke/on APIs.

Read existing dev/build scripts before changing startup dependencies. Preserve
renderer/preload build ordering, relative production paths, and packaged assets.
Production uses `loadFile`, relative Vite assets, and HashRouter. Keep local
packaging separate from publishing; automatic updates require explicit setup.
On Ubuntu, use the launcher's sandbox/AppArmor checks and desktop-session
detection; do not apply Ubuntu setup on every Linux distribution or disable
the sandbox as a default fix. Headless execution needs an intentional test setup.

Verify affected process builds and meaningful IPC/lifecycle behavior through
One tasks. Keep application account credentials separate from One CLI login;
business skills and business features require the user's explicit request.
