这一章介绍 `one create`。可先阅读[模板教程](/zh/tutorials/templates/)选择项目，再继续配置[环境变量](/zh/tutorials/env-vars/)。

## 1. 装 One CLI

```bash
curl -fsSL https://1cli.dev/install.sh | bash
one --version
```

装不上看 [手动安装](/zh/docs/installation/)。

## 2. 跑 `one create`

指定目标目录创建空工作区；省略目录时会提示输入：

```bash
one create my-workspace
```

非交互式（脚本 / CI 用）：

```bash
one create my-workspace --yes
```

关键 flag：

| Flag | 作用 |
|---|---|
| `--name <name>` | 工作区名（覆盖位置参数的 basename） |
| `--yes` | 跳过所有交互，全部走默认 |

完整 flag 列表见 [`one create` 参考](/zh/docs/create/)。

## 3. 跑完写了啥

```bash
cd my-workspace
ls -la
```

会看到：

```
.git/
.config/
AGENTS.md
apps/
mise.toml
one.manifest.toml
packages/
services/
```

看 manifest：

```bash
cat one.manifest.toml
```

manifest 关键字段：

- `version = 2` — TOML 结构版本
- `[workspace]` — 工作区 ID 与展示名称
- `[env.infisical]` — 可选绑定与环境 slug，配置前不存在
- `[projects.<name>]` — 每个项目一张表，空工作区不生成项目表

## 4. `one create` 默认接上的能力

每个新工作区都会默认接上两项基础能力，不用你选：

| Capability | Implementation | 给你啥 |
|---|---|---|
| `env` | Infisical | 绑定后直接注入进程，绑定前使用 shell 环境 |
| `dev` | mise | `one add` 时将项目已有 dev 脚本投影为原生 mise 任务，[`one dev`](/zh/tutorials/dev-local/) 通过 mise 调度 |

`one create` 和 `one add` 都不会默认配置 CI，也不会自动生成 workflow 文件。

## 5. 添加项目

先浏览[模板指南](/zh/docs/templates/)，再使用模板 ID 添加项目：

```bash
one add react-spa --name web --yes
```

需要多个项目时，逐个执行 `one add`。

## 6. 第一次提交

```bash
git status
git add .
git commit -m "chore: scaffold workspace"
```

`one create` 已经跑过 `git init`，第一次 commit 把骨架收进 git。

## 常见错误

| 错误码 | 现象 | 修法 |
|---|---|---|
| `INVALID_NAME` | 名字有非法字符 | 用 `^[a-zA-Z0-9][a-zA-Z0-9_-]*$`（kebab-case 最稳） |
| `WORKSPACE_NESTED_FORBIDDEN` | 在已有工作区里 `one create` | 退出去再起 |
| `EXISTING_TARGET_NOT_EMPTY` | 目标目录已经存在且非空 | 换个名字，或清空目录 |
| `TEMPLATE_NOT_FOUND` | one add 指定的模板不存在 | 跑 [`one templates list`](/zh/docs/templates-cmd/) 或回 [模板页](/zh/tutorials/templates/) |

完整码表：[错误码大全](/zh/docs/error-codes/)。
