---
title: Configure environment variables
description: Sign in to Infisical, bind a workspace, and run commands with injected variables.
---

Infisical stores the values; `one.manifest.toml` records the binding and environment slugs. One CLI injects variables when commands run, without an intermediate `.env` file.

## 1. Sign in

```bash
one login
one whoami
```

The browser session is stored in the system keyring. New workspaces can be created and run without a binding; sign in when managed variables are needed.

## 2. Explicitly bind Infisical

```bash
one env bind
```

Select an existing project or create a new one interactively. Scripts can use `one env bind --create` to create and bind a workspace project, or `one env bind --project-id PROJECT_ID` to bind an existing project. In Dashboard, select a project, then review and save the binding.

## 3. Set a variable

From a workspace containing a project named `api`:

```bash
one env set DATABASE_URL -p api --env dev
```

The terminal asks for the value with hidden input. Without a binding, the command fails with guidance to run `one env bind`. Saving variables never creates a remote project.

At the workspace root, omit `-p` for shared values; interactive `set` offers a scope selector. For scripts, pass a value explicitly and use `--yes` to confirm changes.

## 4. Inspect names

```bash
one env list -p api --env dev
```

`list` shows names only. The CLI does not print secret values; use `one exec` to inject them into commands.

## 5. Run the project

```bash
one exec -p api --env dev -- go run ./cmd/server
one run dev --env dev
```

The binding enables Infisical injection. Unbound projects inherit the shell environment. A configured project's authentication or fetch failure stops execution; local files are not used as a fallback.
